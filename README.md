# 事例検討型Web教材 Ver.9（動作確認版）

## 更新内容

1. 初回回答
2. **追加情報を全員が確認**（判断の材料。ヒントとは分離）
3. **必要なヒントを開きながら最終回答**（最初の回答・追加情報も開閉可能）
4. 初回と最終回答を振り返り、**教員作成の具体的回答例と理由を確認**し、「次に意識する視点」を選ぶ
5. 選んだ視点を画面に示したうえで**別事例に回答**
6. 選んだ視点を意識できたか3択で自己確認し、完了後に別事例の考える手がかりを表示

## GitHubへの適用

GitHubの同名ファイル **app.js / cases.js / index.html / style.css** をこのZIPのファイル内容で更新してコミットしてください。

**config.js は置き換えないでください。** Supabase側のSQL操作は今回不要です。Vercelの最新デプロイがReadyになったら架空データでテストしてください。

## テストの例

- 発行済みコードを入力。未発行コードは拒否されるか
- 初回回答後に追加情報が自動で全員に表示されるか
- 最終回答欄とヒントが**同じ画面**に表示されるか。ヒントを開いた後、入力中の文章が消えないか
- 最終回答→振り返り→回答例・解説→次の視点の選択→別事例→3択自己確認の順に進むか
- リロードしても作業途中のデータが復元できるか
- Supabaseの`learning_events`に`draft`,`extra_open`,`hint_open`（使用時のみ）,`final`,`reflection`,`transfer`,`reflection`が同じ`session_id`で保存されるか
- `reflection`の`payload`の`phase=after_transfer`に`next_focus`および`transfer_self_assessment`が記録されるか

## 大切な注意

- 新しい学習段階は旧版と対応が異なるため、**Ver.8までの入力途中の一時保存からは再開しません**。Ver.9で新しい取り組みとして開始します。過去にSupabaseへ保存された記録は削除しません。
- **Supabaseの既存event_typeだけを利用**しています。振り返りは「最初の事例の後」「別事例の後」で2回保存し、`payload.phase`で区別します。旧Ver.4のCSV整理ツールでは、この新しい区別や自己確認を専用列に表示できない可能性があります。別途更新が必要です。
- 回答例は**教員作成の暫定例**です。利用前に事例の妥当性、評価観点、説明の分かりやすさを吟味してください。操作履歴のみから学習効果や回答品質を判定しません。
- 現在の匿名ユーザーと参加コードの紐づけでは、別端末や共用パソコンでの継続に制限があります。
- 通信失敗時の確実な再送や研究同意管理は未実装です。研究倫理・学内の情報セキュリティ確認前に実学生の回答を収集しないでください。
